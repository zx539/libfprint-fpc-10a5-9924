# FPC 10a5:9924 多指纹录入失败复盘

整理日期：2026-11-12。环境：Fedora 44、FPC `10a5:9924`、fprintd、仓库提供的实验性 libfprint 驱动与 Electron 指纹管理器。

## 现象

最初，用户录入食指和中指后，GUI 只显示一条记录。修复 GUI 的手指选择后，第二根手指仍然不能录入，命令行也能复现：

```text
Enrolling right-index-finger finger.
Enroll result: enroll-duplicate
```

这不是一个单独的显示问题。排查最终区分出 GUI 参数错误和底层驱动身份映射错误。

## 原因一：显示名称没有改变实际录入手指

GUI 最初始终把 `right-index-finger` 传给 `fprintd-enroll`。弹窗中的“指纹名称”只改变本地显示名称，不能改变传给系统的手指参数。因此，把名称改成“中指”仍是在操作食指位置。

修复方法是在弹窗中增加独立的“录入手指”选择，将所选值同时用于录入请求和操作提示；自定义“显示名称”单独保存。此修复随 GUI `0.1.1` 发布，提交为 `ad8e9cb`。

## 原因二：驱动把不相同的身份当作唯一候选匹配

GUI 修复后，命令行仍然报重复，证明问题也存在于 GUI 以外。日志中的关键信号是：

```text
accepting successful on-chip match for the only candidate despite identity mismatch
```

原驱动有一条回退逻辑：只要芯片报告匹配成功，且主机只有一个候选模板，即使返回的身份与候选身份不同，也认为匹配了唯一候选。

例如，主机仅登记身份 A，而芯片识别另一根手指后返回身份 B，驱动仍报告 A 匹配。这既会让第二根手指在 fprintd 的录入前检查中被误判为重复，也会使指定手指的验证结果失去区分能力。

此外，fprintd 登记列表与芯片模板列表并不相同。本次现场检查中，系统只登记了中指，但芯片仍有多条模板记录。早期驱动为已有模板创建随机绑定别名，而传感器识别时继续返回原始身份，造成主机别名与实际匹配身份不一致。清空当前用户登记记录，也不能据此认定芯片内所有历史记录都已消失。

## 驱动修复

1. 删除“唯一候选即匹配”的回退。验证和识别必须通过真实模板身份比较；其他手指或未知身份不能归入已有手指。
2. 重新录入芯片已有的模板时，保存传感器实际返回的身份，保留用户和手指元数据，不再为它生成新的随机别名。
3. 已存在的模板已经持久保存，直接进入枚举确认阶段。实机验证发现，再次提交保存会出现 `Save DB failed: -13`，因此该路径跳过新的绑定和保存。
4. 新绑定后的枚举刷新只选择与本次待确认身份精确一致的记录，不再任意选择列表中的另一条类型 4 身份。
5. `fpi_print_set_type()` 只能初始化一次。刷新模板身份时，先读取 `fpi-type`，仅在未初始化时设置，修复日志中的类型断言错误。

驱动修复提交为 `7e26314`。可分发源码位于：

- `patches/0001-fpcmoc-add-10a5-9924-experimental-support.patch`
- `tests/fpc-identity.c`
- `scripts/test-fpc-identity.py`

## 如何验证

新增测试直接执行真实驱动回调和 libfprint 的模板序列化、比较逻辑，仅替换设备报告和状态机边界，不需要传感器：

```bash
python3 scripts/test-fpc-identity.py ./libfprint-9924
meson test -C libfprint-9924/build-fpc9924 --suite unit-tests --print-errorlogs
```

回归测试覆盖：身份 B 不能匹配唯一候选 A；身份 A 仍能正常匹配；多个候选可独立识别；旧模板重新登记保留真实身份且跳过重复保存；刷新只确认本次绑定且不重复初始化模板类型。测试先在旧实现中失败，再在修复后通过。

补丁还在干净的上游文件上执行了应用检查，并确认应用结果与测试过的源码一致。libfprint 的三组现有单元测试全部通过。

现场最终完成了以下验证：

```text
Fingerprints for user ...:
 - #0: right-index-finger
 - #1: right-middle-finger

右手食指：verify-match
右手中指：verify-match
```

## 升级与恢复

此问题的核心修复位于 libfprint，不在 GUI RPM 内。其他机器需要应用更新后的补丁、重新构建并安装驱动，再重启 fprintd；只更新界面不会替换系统驱动。

从旧驱动升级时，应重新录入原有手指，修正历史别名映射，然后录入其他手指。不要仅为处理误判而反复清空模板，也不要把“当前用户没有登记指纹”解释为“芯片完全为空”。本机已经完成驱动安装和两根手指的实机验证。

## GUI 改进（0.2.0）

GUI 0.2.0 已加入真实操作反馈，让采集进度和处理建议跟随传感器结果更新：

- 从命令输出持续读取采样、重试、成功和错误事件，通过 IPC 发送给当前操作窗口。
- 从设备读取采样总数，用已接受的采样次数计算百分比；未知总数时展示不确定进度，不按时间虚构百分比。
- 未收到完成状态且命令未成功退出前，百分比上限为 99%；保存成功后才显示 100%。
- 手指未居中、需要抬起、图像不清晰等可恢复提示不增加采样数，也不终止整个录入。
- 重复指纹、空间不足、设备断开、权限不足和设备占用显示中文原因，并提供重试和原始详情。
- 操作具有独立 ID，过滤旧事件；取消后等待原进程退出，再允许新的操作。录入和验证期间暂停界面列表轮询，避免争抢设备。
- 扫描线、采样脉冲、进度环、成功勾选、错误反馈采用对应状态驱动的动画，并遵循系统减少动态效果设置。

新增的 9 项操作流测试和完整 Electron 界面验收均通过。界面验收使用独立配置和模拟指纹命令，覆盖主进程、IPC、预加载桥接、手指选择、进度、重试、错误详情、取消、旧事件过滤、深色模式、小窗口和减少动态效果，不改动真实指纹。另已只读确认本机 fprintd 报告的总阶段数为 26。运行方法：

```bash
cd electron-app
npm test
npm run test:ui
```

## 排查经验

先用 `fprintd-list` 核对系统登记，再用 `fprintd-enroll` 获取确切错误；需要确认底层状态时，再只读枚举芯片模板。把 GUI 名称、fprintd 手指位置、芯片模板身份分别核对，才能识别参数错误和身份映射错误。

不能用“只剩一个候选”补偿身份不一致，也不能仅凭编译成功或单根手指可以验证，就断言多指纹功能正常。最终验收至少包括两根手指同时登记，并分别验证成功。
